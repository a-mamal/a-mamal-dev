## What is a-mamal.dev?

a-mamal.dev is my personal development laboratory and documentation site. It's where ideas, experiments and technical decisions come to life, and where I write down what I learn along the way. It's also the site that shows my playful side and personality.

> Build. Break. Learn. Repeat.

It's not a finished product, and it isn't meant to be. It's unfinished by design, always evolving, and it favors experimenting over perfection.

## How it differs from a-mamal.com

My professional portfolio at [a-mamal.com](https://a-mamal.com/) presents selected work, with a focus on clarity. It's still a work in progress too, but its purpose is different. This site is where I explore. It has room for raw sketches and early-stage thinking, and it captures the whole journey from first idea to finished form, if there is one.

## What's on the site

- **Home**: the starting point.
- **Projects**: what I've built or am building, with status and links.
- **Logbook**: articles and journal entries, including Sherlock's journal.
- **Documentation**: documentation pages for my projects, including this site.
- **About**: a bit about me.

## How it's built

This is a remake of the original site, which was built with Laravel and Blade and is now archived at [initial.a-mamal.dev](https://initial.a-mamal.dev).
The new version is a single repository with two applications: a frontend built with React, TypeScript and Vite, and a Laravel API that serves the data.
The Architecture page explains how they fit together.

## Learning in public

Mistakes, experiments and unfinished ideas are expected here. The repository is public, and so are these pages. If you have an idea or a request, or you spot something that needs fixing (even a typo or an unclear sentence), you're welcome to [open an issue](https://github.com/a-mamal/a-mamal-dev/issues) or propose a fix with a pull request on [GitHub](https://github.com/a-mamal/a-mamal-dev). You can also follow along on the [project board](https://github.com/users/a-mamal/projects/6).

If you're just starting out, I add [good first issues](https://github.com/a-mamal/a-mamal-dev/issues?q=is%3Aopen%20is%3Aissue%20label%3A%22good%20first%20issue%22) for exactly that reason: everyone needs a safe place to start. Take your time, and don't worry about breaking things. We're all learning.
